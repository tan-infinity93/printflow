1. PROJECT OVERVIEW
--------------------------------------------------------------------------------

A browser-based document design and printing tool built entirely in vanilla
HTML / CSS / JavaScript (no frontend framework). Users log in, design multi-page
documents on an SVG canvas, apply templates, and export to PDF or raw JSON/SVG.
All persistence is handled via IndexedDB (templates, audit logs, version history)
and sessionStorage (UI state, settings, zoom, grid).

Primary use-cases
  - Designing letters, invoices, and envelope layouts
  - Placing text boxes, image boxes, and tables on an SVG canvas
  - Saving, versioning, and exporting documents

3. DATABASE SCHEMA  (IndexedDB — "PrintingDB" v1)
--------------------------------------------------------------------------------

Store               Key       Description
---------------------------------------------------------------------------
printingUsers       id        User accounts (userName, passWord hash).
printingTemplates   id        Custom and gallery templates (dom-json snapshot).
printingAuditLogs   id        Timestamped action ledger.
printingVersionLogs id        Full multi-page canvas snapshots for version restore.

All stores share a helper layer in scripts.js:
  saveRecordToDB / getAllRecordsFromDB / getSingleRecordFromDB /
  deleteSingleRecordFromDB / checkLoginUser

The DB is opened once via a cached _dbPromise and reused across all operations.
A custom event 'printflow:dbwrite' fires on every write, driving stats.js refresh
without polling.

4. CANVAS ARCHITECTURE
--------------------------------------------------------------------------------

The workspace is a single SVG element (#workspace) that spans all pages:

  SVG root
    ├── <g id="rulers-layer">          — horizontal + vertical mm rulers
    └── (per page, p = 1…N)
        └── <g id="pageGroup-p">
            ├── <rect id="pageRect-p">     — white paper background
            ├── <g id="grid-layer-p">      — grid overlay (url(#gridPattern))
            ├── <rect id="safeZone-p">     — dashed safe-zone border
            ├── <g id="content-layer-p">  — user elements (text/image/table groups)
            └── <text class="page-watermark"> — small "P1" badge top-right

Element types on the canvas:
  - svg-text-group   : <g> wrapping <text> + highlight <rect>
  - svg-image-group  : <g> wrapping <image> + corner resize handles
  - svg-table-group  : <g> of cell <g>s (each with <rect> + <text>) + grip handle

All elements support:
  - Free drag (SVG translate transform, snap-to-grid optional)
  - Context menu (right-click / long-press): edit, style, layer order, alignment
  - Undo / redo (JSON snapshot stack, max 20 deep, all pages)
  - Lock / unlock
  - Overlap detection warning

Multi-page:
  - Up to 5 pages, each a vertically stacked page group in the SVG
  - Page gap: 15 mm between pages (PAGE_GAP_MM in layout.js)
  - Active page tracked in sessionStorage; clicking a page activates it
  - addPage / removePage manage the SVG and update the Pages panel UI

Canvas div sizing is now dynamic: updateCanvasSize() in layout.js sets the
#canvas div's width/height to match the SVG on every resize, preventing the
grey background shadow from overflowing the page area.

7. KNOWN ISSUES / LIMITATIONS
--------------------------------------------------------------------------------

  1. No persistence of canvas between sessions for anonymous / unversioned state.
     The user must manually click "Save Current Version" to preserve work.
     Auto-save on a timer or before tab close would reduce data loss risk.

  2. PDF export uses html2canvas which rasterises the SVG at 3× scale. Fine for
     most use cases, but vector quality (e.g. text sharpness at very high zoom)
     is limited. A direct SVG-to-PDF pipeline (e.g. svg2pdf.js) would be sharper.

  3. updateTableDimensions (context menu Rows/Columns change) uses a fixed
     colWidth = 20mm / rowHeight = 10mm rather than reading the existing cell
     dimensions. Resizing a table resets all custom widths.

  4. makeTableEditable (double-click cell to edit via prompt()) is commented out.
     Cell editing is only possible via the context menu input field.

  5. There is one duplicate id "app-storage-usage" in workspace.html (lines 1078
     and 1139). The second card (App Downloads) should have a unique id.

  6. The "Save Export as HTML" toggle in Settings switches the export format but
     the label says "HTML" whereas the actual alternate format is SVG. The label
     should read "SVG".

  7. Dark mode state toggle (Settings > Dark Mode) uses a plain <input type=checkbox>
     whose checked state is not restored from sessionStorage on reload, so the
     toggle visually appears unchecked even when dark mode is active.

  8. loadSelectedTemplateFile and deleteSelectedTemplateFile are called from inline
     onclick strings in dynamically generated HTML inside openTemplateGalleryModal.
     These functions must remain globally scoped; any future module bundling will
     break them.

  9. The letters.js event listener for .documenttype uses a foreach over
     querySelectorAll at load time. If the dropdown items are ever rendered
     dynamically the listeners will not attach.

  10. No mobile / touch support for drag operations on the SVG canvas.
      Drag uses mousedown/mousemove/mouseup only.

8. TECHNICAL DEBT
--------------------------------------------------------------------------------

  - Commented-out dead code throughout scripts.js and letters.js (old positioning
    logic, old File-object image code). Should be cleaned up.

  - scripts.js is a single 2 469-line file. Splitting into logical modules
    (canvas.js, drag.js, zoom.js, export.js, ui.js) would improve maintainability.

  - All functions are global (window scope). A module pattern or IIFE wrapping
    would reduce collision risk.

  - index.html and workspace.html share scripts.js. This creates a tension: the
    script guards against running canvas code on the login page via the
    svgRoot-existence check, but it's fragile. A proper split (shared-utils.js
    + workspace-only.js) would be cleaner.

  - The LETTER_LAYOUT_ELEMENTS / INVOICE_LAYOUT_ELEMENTS / ENVELOPE_LAYOUT_ELEMENTS
    constants contain hardcoded personal name/address data (Tanmoy Karmokar,
    Chinmay Karmokar etc.) intended as placeholders. These should be
    template-variable driven (e.g. {{sender_name}}).

  - restoreVersion uses a hardcoded layout call sequence that duplicates the
    onloadInit logic. A shared restoreState(pages, pageSize) helper would reduce
    duplication.
