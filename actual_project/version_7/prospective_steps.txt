0. CODEBASE CONTEXT & NON-NEGOTIABLE CONVENTIONS
--------------------------------------------------------------------------------

Stack: vanilla HTML/CSS/JS, no build system, no npm. All libs via CDN.
Pages: index.html (login) and workspace.html (app). index.html loads ONLY
shared-db.js — NEVER add workspace scripts to it.

Script load order in workspace.html (do not reorder):
  shared-db.js → layout.js → canvas-elements.js → canvas-interactions.js
  → scripts.js → letters.js → darkmode.js → exports.js → imports.js
  → stats.js → help.js → bootstrap → html2canvas → jspdf → svg2pdf

Canvas model:
  - One SVG (#workspace); SVG user units == millimetres.
  - Per page p: <g id="pageGroup-p"> containing pageRect-p, grid-layer-p,
    safeZone-p, content-layer-p, page-watermark, page-active-badge-p.
  - USER CONTENT LIVES ONLY IN content-layer-p. Anything outside it is
    chrome and is automatically excluded from JSON exports/snapshots.
  - Element types: .svg-text-group, .svg-image-group, .svg-table-group.
    All carry class "design-object" + attribute elementType.

Persistence:
  - IndexedDB "PrintingDB" v1, stores: printingUsers, printingTemplates,
    printingAuditLogs, printingVersionLogs. Helpers in shared-db.js
    (saveRecordToDB(obj, storeName), getAllRecordsFromDB(storeName), ...).
    Every write dispatches CustomEvent "printflow:dbwrite" (stats.js listens).
  - sessionStorage: per-tab UI state (pageSize, totalPages, currentPage,
    gridSize, snapToGrid, displayMode, stats, appSettings...).
  - localStorage: cross-tab/persistent (printflow_draft, loggedInUser,
    showSplashScreen, inlineCellEdit, vectorPdfExport).

UNDO CONTRACT (critical — documented in scripts.js):
  Snapshots hold the state BEFORE a change. Either call captureSnapshot()
  at the START of a mutation, or serialise via _currentAllPagesSnapshot()
  early and push with _pushUndoSnapshot(str) once the change is confirmed.
  NEVER snapshot after mutating. Drafts auto-persist post-change via
  _scheduleDraftSave() — do not write printflow_draft manually.

EXPORT EXCLUSION CONTRACT (critical):
  UI chrome must not appear in any output. Existing classes already wired
  into all pipelines: .img-resize-handle, .svg-table-grip, .page-watermark,
  .text-highlight, .cell-edit-fo. If you add new chrome, you MUST update:
    1. domToJson() in exports.js (skip list)
    2. _exportRasterPDF ignoreElements (scripts.js)
    3. _exportVectorPDF clone-strip selector (scripts.js)
    4. raw SVG export hide list (exports.js confirmRawExportFile)
    5. enter/exitPreviewMode selectors (scripts.js)
  Easiest path: reuse class "page-watermark" for page-level chrome, and
  toggle per-instance visibility via style.display (NOT the visibility
  attribute — preview restore overwrites visibility on all matches).

Settings pattern: a row in workspace.html settingsModal (android-switch-m3
checkbox with id + slider onclick="toggleX()"), a toggleX() in exports.js
persisting localStorage, and checkbox sync in openSettingsModal (scripts.js).
Follow this exactly for new settings.

Style: global functions (no modules), const arrow functions, 2-space indent,
showToast(msg, "success|warning|danger|info") for feedback, audit-log every
significant action to printingAuditLogs ({id: crypto.randomUUID(), entry,
timeStamp: ISO string}).

Validation after every task: `node --check` on each touched JS file; verify
every onclick/onchange/oninput in HTML resolves to a defined function; no
duplicate ids; manually trace one undo+redo cycle for any new mutation.

1. TEMPLATE VARIABLES + MAIL MERGE  (build FIRST — highest B2B value)
--------------------------------------------------------------------------------

1.1 Template variables
  - Syntax: {{variable_name}} inside any text element or table cell.
  - Replace hardcoded sample data in LETTER/INVOICE/ENVELOPE_LAYOUT_ELEMENTS
    (letters.js) with placeholders: {{sender_name}}, {{sender_company}},
    {{recipient_name}}, {{invoice_number}}, {{date}}, etc.
  - New file merge.js (load after letters.js):
      extractVariables() → scans all content layers' <text>/tspans with
        /{{\s*([a-zA-Z0-9_]+)\s*}}/g, returns unique names.
      applyVariables(valueMap, target = live canvas or a cloned snapshot)
        → replaces placeholders; for live replacement call captureSnapshot()
        FIRST, then mutate, then wrapSvgText() on affected text elements
        (use textEl.dataset.rawText as source of truth, update it too).
  - Reserved auto-variables, resolved at merge time, not from CSV:
      {{date}} (getCurrentDate()), {{page}} (page no), {{seq}} (section 3).

1.2 Fill-in form (single document)
  - New modal in workspace.html (id="variableFillModal"): on open, call
    extractVariables(), render one labelled input per variable, "Apply"
    button → applyVariables() on the live canvas. Add a "Fill Variables"
    button to the document-preset card.

1.3 Mail merge (batch)
  - New modal (id="mailMergeModal"), launched from print-controls card.
  - CSV input: <input type="file"> + a hand-rolled parser (handle quoted
    fields with commas and CRLF; ~40 lines; no external lib). First row =
    headers. Show a mapping table: each extracted variable → dropdown of
    CSV headers (auto-match case-insensitively on equal names).
  - Preview: render row 1 merged onto the canvas (NON-destructive: snapshot
    canvas state first via _currentAllPagesSnapshot(), restore after).
  - Generate: for each CSV row, apply variables to an in-memory clone and
    export. Output mode A (default): one combined PDF — iterate rows,
    apply to live canvas, run existing _exportRasterPDF/_exportVectorPDF
    page loop into a SHARED jsPDF instance (refactor those two functions
    to optionally accept an existing pdf instance and a skipSave flag),
    restore canvas afterwards. Output mode B: one PDF per row, zipped is
    NOT possible without a lib — instead trigger sequential downloads with
    row-derived filenames ({{recipient_name}}.pdf, sanitised).
  - Progress UI: Bootstrap progress bar in the modal; yield to the event
    loop between rows (await new Promise(r => setTimeout(r))) so the UI
    paints. Cap batch at 200 rows with a toast warning above that.
  - Audit-log: "Mail merge: N documents from file.csv".

8. OFFLINE LICENSING (signed keys, tiers, trial)
--------------------------------------------------------------------------------

  - New file license.js, loaded EARLY in workspace.html (after shared-db).
  - Key format: base64(JSON payload).base64(signature). Payload:
    { licensee, tier: "trial"|"standard"|"pro", seats, exp: "YYYY-MM-DD",
      features: ["mailMerge","vectorPdf","labels"] }.
  - Verify with SubtleCrypto ECDSA P-256: embed the PUBLIC key (JWK) as a
    const; crypto.subtle.importKey → crypto.subtle.verify over the payload
    bytes. (Generation script for the private key is OUT of app scope —
    provide it as tools/generate_license.mjs for Node, not loaded by the
    app.)
  - API: await License.activate(keyString) (validates, stores in
    localStorage "printflow_license"), License.current() → decoded payload
    or {tier:"trial"}, License.has(feature) → boolean.
  - Enforcement points (fail soft with an upsell toast, never crash):
      mail merge row cap 10 on trial; vector PDF off on trial;
      pages cap 2 on trial (addPage check); TRIAL watermark on every
      export (mechanism from section 7).
  - Expiry: warn 14 days out (toast on load); past exp → drop to trial.
    Clock-tamper tolerance: store lastSeenDate, if now < lastSeenDate
    treat as expired-suspicious and drop to trial.
  - UI: "License" entry in settings modal — shows current tier/expiry,
    input to paste a key, Activate button.

12. 3D CANVAS INSPECTOR (WebGL — "Firefox Tilt" style)
--------------------------------------------------------------------------------

Goal: an interactive 3D exploded view, like Firefox's old DevTools
"Tilt"/3D View — every element extruded into a stacked box by hierarchy
depth and z-order, orbitable in realtime, click any box to inspect/select
the real element.

SCOPE — CANVAS LAYER ONLY: visualise ONLY the #workspace SVG document
(page groups and their content layers). The surrounding app DOM — navbar,
side panels, modals, buttons — is NEVER walked or rendered. The model is
of the user's DOCUMENT, not the webpage. PrintFlow's canvas is ideal for
this: SVG user units are mm, so the 3D model is DIMENSIONALLY TRUE.

12.1 Library & loading
  - Three.js via CDN, version-pinned UMD build (e.g.
    https://cdnjs.cloudflare.com/ajax/libs/three.js/0.158.0/three.min.js).
    LAZY-LOAD it: inject the <script> tag only the first time the
    inspector opens (injectScriptOnce(url) helper, cache the promise).
    Do NOT add it to the static script list — keeps normal load light.
  - Do not rely on THREE.OrbitControls (separate examples file);
    implement minimal controls by hand (12.4) — ~60 lines.

12.2 UI entry point
  - New file inspector3d.js, loaded statically (it's small; Three.js is
    the lazy part). Navbar button (cube icon) + Settings switch
    "3D Inspector (beta)" following the standard settings pattern
    (toggle3dInspector / localStorage "inspector3d" gates the button).
  - Opening: full-viewport overlay div (id="inspector3dOverlay",
    z-index above everything, dark backdrop) containing the WebGL
    <canvas>, a close button (Esc also closes), a legend, and an info
    side-panel (12.5). While open, suspend canvas keyboard shortcuts
    (undo/redo handler: early-return if overlay visible).

12.3 Scene construction (the core mapping)
  - For each page p: a thin base plate — THREE.BoxGeometry(pageW, pageH,
    0.5) light grey, at depth z = 0. Pages laid out side by side with a
    40 mm gap (NOT stacked like the SVG — side-by-side reads better
    in 3D).
  - Walk content-layer-p children recursively. For every visualised node
    compute its page-relative bbox in mm:
      bbox = el.getBBox(); accumulate ancestor translate() transforms
      (reuse the translate-regex pattern from canvas-interactions._getTranslate).
      Rotated/flipped images: use the group's bbox (axis-aligned is fine).
  - Each node → THREE.Mesh(BoxGeometry(w, h, EXTRUDE), material) where
    EXTRUDE = 1.5 mm, positioned at
      x: bboxCx, y: -bboxCy (SVG y-down → three y-up), z: depth * 4 mm.
    depth = 1 for top-level groups, +1 per nesting level (table cell
    groups at 2, their rect/text at 3). Add +0.5*siblingIndex/10 to z so
    overlapping same-depth elements never z-fight and z-order is visible.
  - Colour by type (match app accents): text #0d6efd, image #6f42c1,
    table #198754, shape #fd7e14, unknown #6c757d. Material:
    MeshLambertMaterial, transparent, opacity 0.55 (Tilt's glass look) +
    a THREE.LineSegments(EdgesGeometry) outline per box.
  - EXCLUDE all chrome (the export-exclusion classes: img-resize-handle,
    svg-table-grip, page-watermark, text-highlight, cell-edit-fo,
    align-guide, label-guide). Optional "show chrome" checkbox renders
    them as 0.2-opacity ghosts.
  - Lighting: one ambient + one directional; renderer with antialias,
    setPixelRatio(devicePixelRatio capped at 2).
  - Element cap: if total meshes > 2000, collapse depth>2 nodes into
    their parent and toast a notice (perf guard).

12.4 Interaction
  - Custom controls on the overlay canvas:
      left-drag = orbit (spherical coords around scene centre),
      wheel = dolly zoom (clamp 50–2000 mm), right/middle-drag = pan.
      Touch: 1-finger orbit, 2-finger pinch zoom + pan (reuse the
      touch-event patterns from canvas-interactions.js).
  - requestAnimationFrame loop ONLY while the overlay is open AND the
    camera/scene is dirty (render-on-demand; set a needsRender flag in
    control handlers) — zero GPU cost when idle.
  - Raycasting on click (THREE.Raycaster from camera through pointer):
      hover → emissive tint on the hit mesh + cursor pointer;
      click → select: brighten mesh, show info panel (12.5), and flash
      the REAL SVG element behind the overlay (apply a temporary CSS
      outline/filter for 800 ms so the user can correlate).
  - Double-click a mesh → close the inspector and open that element's
    context menu on the 2D canvas (call showContextMenu with the target
    group; synthesize the event arg minimally like the long-press path
    already does).
  - Keyboard: R resets camera, 1–5 jump camera to page n, Esc closes.

12.5 Info panel (right side of overlay)
  - On selection show: element type, id, page no, x/y position (mm),
    w/h (mm), nesting depth, sibling z-index, locked?, and for text the
    first 80 chars of content; for images natural vs placed size; for
    tables rows×cols.
  - Buttons: "Locate" (re-flash the SVG element), "Edit in canvas"
    (the double-click action), "Bring to front / Send to back" — these
    call the EXISTING z-order functions (they captureSnapshot correctly),
    then rebuild the scene (12.6).

12.6 Realtime sync
  - Build the scene from live DOM on open. While open, attach ONE
    MutationObserver on #workspace (subtree, childList, attributes:
    transform/width/height) with a 150 ms debounce → dispose + rebuild
    scene graph (geometry/material .dispose() on every removed mesh —
    REQUIRED to avoid GPU leaks). Disconnect observer on close.
  - This makes the view live: undo/redo, drags (if user has the app in
    a split view), merges etc. update the 3D model automatically.

12.7 Teardown & safety
  - On close: cancel RAF, disconnect observer, dispose all geometries/
    materials/renderer (renderer.dispose(), forceContextLoss optional),
    remove overlay from DOM. Re-enable keyboard shortcuts.
  - WebGL unavailable (no context): toast "3D inspector needs WebGL" and
    never show the button again that session.
  - This is a READ-ONLY visualisation + selection bridge: it must never
    mutate document content itself (all mutations route through existing
    undoable functions). No export pipeline involvement — nothing to add
    to the exclusion contract EXCEPT the overlay div itself, which lives
    outside #workspace and is therefore already invisible to all exports.

12.8 Why this sells (B2B framing)
  - Print-shop QA: instantly see stacking mistakes (white box covering
    text), elements outside the safe zone (render the safe zone as a
    translucent red frame at z=0.6), and cross-page consistency at a
    glance. Position it as "X-ray view" in marketing, not a dev tool.
